## 这个项目在做什么

本项目不是 EzRemove 产品代码，也不是刷量脚本。它是一个增长研究与执行拆解仓库，目标是回答三个问题：

1. EzRemove 应该如何围绕 `watermark remove`、`watermark remover`、`remove watermark` 这些商业词建立搜索入口。
2. 如何把 X/Twitter、KOL、PR、工具页、长尾页面、内链外链和 AI Search/GEO 组织成一个真实增长系统。
3. 在去水印这个高商业意图但有版权风险的品类里，哪些动作能做，哪些动作不应该做。

最终产物是一份 GitHub Pages 静态报告，供团队复盘、讨论、执行和对外分享。

## 核心知识点

### 1. 增长不是单点 SEO 技巧

`watermark remove` 的增长不是只写几篇文章或堆关键词，而是一个完整链路：

用户需求被社媒/KOL/PR 唤起 -> 用户搜索品牌或问题词 -> SEO 页面承接 -> 工具体验转化 -> 数据复盘再反哺内容和产品。

### 2. 关键词要分层，不要堆词

核心商业词适合首页和功能页承接，例如：

- `watermark remover`
- `watermark remove`
- `remove watermark`
- `remove watermark from image`
- `remove watermark from video`

长尾词适合教程页、场景页、对比页和 FAQ 页承接。每个页面都要有真实任务、工具入口、示例、边界说明和下一步，而不是只为了覆盖关键词。

### 3. 产品体验是流量放大的前提

SEO、KOL 和 PR 能把流量带进来，但上传、处理、预览、下载、免费额度、支付和版权提示必须稳定。产品体验不到及格线时，流量只会放大跳出、差评和不信任。

### 4. PR/KOL 应该制造真实品牌需求

可以通过创作者演示、对比测评、免费工具体验和案例传播，让用户真实记住并搜索 EzRemove。不要做机器人搜索、虚假点击、群控账号或诱导式刷词。

更健康的目标是让这些查询自然增长：

- `ezremove`
- `ezremove watermark remover`
- `ezremove remove watermark`
- `best watermark remover alternatives`

### 5. 内链和外链本质是信任与路径设计

内链不是机械传权重，而是帮助用户从教程、对比、FAQ 和场景页回到核心工具页。外链也不应该追求数量，而应优先来自图片编辑、视频剪辑、电商卖家、AI 工具目录、创作者工作流等垂直场景。

### 6. GEO / AI Search 要做可引用资产

面向 ChatGPT、Gemini、AI Overview 等 AI 搜索场景，页面需要更清楚地回答问题，并保持实体一致：

- EzRemove 是什么
- 支持哪些素材类型
- 怎么使用
- 有什么限制
- 是否免费
- 什么时候可以合法去水印
- 和其他工具有什么差异

FAQ、How it works、对比页、基准测试页和合规说明，都比泛泛博客更容易成为 AI 可引用资料。

### 7. 去水印必须先定义合法边界

`watermark remove` 有高转化潜力，也有版权和平台风控风险。页面表达必须强调：

- 处理自己拥有或获得授权的素材；
- 清理自有图片里的时间戳、logo、遮挡文字或草稿标记；
- 不鼓励移除他人作品水印后商用；
- 不鼓励绕过图库、平台或创作者授权。

长期增长要建立在真实用户价值和合规边界上。
